Canonical control-plane API used by the dashboard and CLI.

Normative draft for administrative bootstrap, tenancy, immutable configuration, secrets, users, installations, usage, audit and self-tests. Cookie-authenticated mutations also require origin validation and `X-CSRF-Token`; scoped bearer API tokens are not subject to browser CSRF but receive the same capability checks. Browser sessions receive the CSRF value in both the login/bootstrap response header and a Secure, SameSite=Strict, non-HttpOnly `__Host-latchway_csrf` cookie so a same-origin console reload can recover without persisting it. Every successful or rejected mutation produces a redaction-safe audit event.

## Authentication schemes

| Scheme | Type | Location | Credential |
| --- | --- | --- | --- |
| `AdminCookie` | apiKey | cookie | `__Host-latchway_admin` |
| `AdminToken` | http | Authorization header | `opaque-admin-api-token` |

Cookie-authenticated mutations also require the same-origin CSRF
contract declared by their `X-CSRF-Token` parameter. Bearer tokens are
scoped and are supplied through an environment variable, never a command
argument. Every non-success response resolves to the canonical RFC 9457
problem contract in [Errors](/reference/errors).

## Mutation safety

Configuration replacements use strong ETags. Write-only secrets and
one-time API-token values are never returned after creation. A response
with `operation_indeterminate` may represent a committed mutation; use its
operation ID and durable state to reconcile before retrying.

Use the [CLI reference](/reference/cli) for credential-safe automation and
the [configuration schema](/reference/config-schema) for the immutable
environment document.
