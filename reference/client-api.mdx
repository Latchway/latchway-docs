DPoP-bound client sessions and AI-compatible proxy routes.

Normative draft for current wire protocol version 2. Legacy wire protocol version 1 remains accepted for compatible installation/session clients. Identity, attestation and DPoP establish a short-lived installation session. Protected AI requests name an application feature; clients cannot select trusted users, routes, prices or upstream credentials. Browser requests carry one exact canonical HTTPS `Origin`; it is authorized against the active web-attestation selection on every session and protected data-plane operation. Native requests omit it.

The SDK owns platform attestation, secure key storage, RFC 9449 DPoP,
origin enforcement, renewal, bounded parsing, redaction, and safe replay.
The operation index is a wire reference, not a replacement SDK recipe.

## Authentication schemes

| Scheme | Type | Location | Credential |
| --- | --- | --- | --- |
| `DPoPAccessToken` | http | Authorization header | `DPoP` |
| `DPoPProof` | apiKey | header | `DPoP` |

A plus sign in the operation table means that the same request requires
both schemes. Discovery operations explicitly declare an unauthenticated
alternative. Every non-success response resolves to the canonical RFC 9457
problem contract in [Errors](/reference/errors).
