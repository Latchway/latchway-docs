## 1. What this integration does

The source Class A helper passes a guarded custom fetch and Latchway base URL
through `ChatOpenAI` client configuration. It does not implement chains, agents,
graphs, memory, retrievers, or tool execution.

## 2. Supported framework versions

`@langchain/openai` `1.5.10` is the exact locally tested experimental version.
The generated compatibility registry is canonical; no supported range is
published.

## 3. Supported Latchway versions

Use published `@latchway/langchain` 1.1.0 with `@latchway/client` 1.0.0.
Chat function tools under input/total quotas require server 1.0.4+; the bounded
Responses profile requires 1.0.2+. Contract 1.0.0 and wire 2 are unchanged.

## 4. Security level

| Capability | Target and current status |
| --- | --- |
| Full DPoP preserved | Passes local chat and embeddings adapter tests through the guarded Latchway transport |
| Private key remains native | Not applicable to the JavaScript adapter; native hosts must provide a native-backed transport |
| Streaming | Conditional; hosted common conformance remains pending |
| Cancellation | Local abort propagation passes |
| App extensions | Not provided by this JavaScript integration |
| Structured output | Conditional; not release-evidenced |
| Tool calls | Conditional; not release-evidenced |
| Protocol | Released source wire 2 supports Chat Completions and embeddings for the tested seam |

## 5. Install packages

Install `@latchway/langchain@1.1.0`, `@latchway/client@1.0.0`,
`@langchain/core@1.2.9`, `@langchain/openai@1.5.10` and `openai@7.8.0`.
For a native host, follow the [React Native setup](/clients/react-native/framework-integrations)
for native modules, application-owned runtime compatibility and exact examples.

## 6. Create the Latchway client

Use a platform Latchway client that owns refresh, key storage, DPoP signing, and
origin checks.

## 7. Bind a feature

Bind one feature ID when creating the model helper. Do not use LangChain's model
field to select a physical model.

## 8. Create the framework client

Use `createLatchwayChatOpenAI({latchway, feature, chatOptions: {
useResponsesApi: false, maxTokens: 1024, maxRetries: 0}})` for a Chat feature.
The guarded native/client fetch owns authentication and DPoP; do not pass a
provider key or physical model to the app.

## 9. Send a non-streaming request

The local chat adapter exercises the non-streaming request path while preserving
LangChain message types. Hosted `invoke` and `batch` evidence remains a release
gate.

## 10. Send a streaming request

`stream` must remain incremental and cancellable without buffering or replay.

## 11. Use tools

Use `bindLatchwayTools(model, tools)` for local function definitions with
explicit strict/serial defaults. Server 1.0.4 accounts for Chat tools and
expanded schemas under input/total quotas; earlier servers reject that shape.
The app owns authorization, argument validation, execution, timeouts and a
bounded loop. Replay complete assistant calls plus correlated tool results.
See [Chat tool limits](/clients/react-native/framework-integrations#chat-function-tools-and-quotas).

## 12. Use structured output

Structured output must preserve LangChain's validation and error behavior.

## 13. Handle cancellation

Cancellation must reach the underlying request and suppress automatic replay.

## 14. Handle quota failures

Surface the Latchway problem and request ID without disguising it as an OpenAI
credential error.

## 15. Handle session renewal

Framework retries and Latchway refresh must not combine into unbounded attempts.
Every permitted attempt requires a new DPoP proof.

## 16. Known limitations

LangChain and its transitive OpenAI client can change their networking seams
independently. Both ranges require testing.

## 17. Verify the integration

Required cases include `invoke`, `stream`, `batch`, tools, structured output,
cancellation, retry behavior, and metadata propagation.

## 18. Troubleshooting

Confirm the guarded custom fetch reached the underlying OpenAI client and that
no framework retry reused a proof.
