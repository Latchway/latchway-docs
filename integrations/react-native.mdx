## 1. What this integration does

Pass a native-backed Latchway client to a framework's custom-fetch adapter.
Swift or Kotlin owns session credentials, keys, attestation, DPoP and network
dispatch. Frameworks receive safe response data and stream chunks.

For LangChain, follow [React Native framework setup](/clients/react-native/framework-integrations).
For application configuration and supplied identity, follow the
[quickstart](/clients/react-native/quickstart). Standalone and embedded React
Native use the same API with no Firebase dependency or native auth bootstrap.

## 2. Supported framework versions

The application guide uses `@latchway/langchain` 1.1.0,
`@langchain/core` 1.2.9, `@langchain/openai` 1.5.10 and `openai` 7.8.0.
The [compatibility matrix](/reference/compatibility) retains its independently
versioned conformance evidence, including pre-release or experimental rows.
Package publication does not silently promote those rows or establish a fresh
physical-device result for every framework.

## 3. Supported Latchway versions

The shared-account line uses React Native 1.2.0, iOS 1.2.0, Android 1.1.0,
JavaScript client 1.1.0 and server 1.1.1, with contract 1.1.0 and wire 3.
See [Release status](/release-status) for registry receipts and the
[SDK source bundle](/reference/sdk-bundles/react-native) for documentation
commits and exact source regions.

## 4. Security level

| Capability | Boundary |
| --- | --- |
| Full DPoP | Native signing and session-key binding; JavaScript does not construct authenticated proofs |
| Private key remains native | Native Keychain/Keystore owns key material; the bridge returns no private key |
| Streaming | Native-backed incremental response consumption with backpressure |
| Cancellation | `AbortSignal` reaches native dispatch; local tool cancellation remains app-owned |
| App extensions | Not granted by this main-app framework integration |
| Structured output | Requires the matching route/model and supported schema |
| Tool calls | Transported as bounded protocol content; authorized execution remains application-owned |
| Protocol | Shared native accounts use wire 3; legacy compatible wire-1/2 routes remain on the gateway |

These boundaries do not replace tests of your signed application and its
required App Attest or Play Integrity policy.

## 5. Install packages

Use the exact [installation coordinates](/clients/react-native/installation)
and [LangChain runtime setup](/clients/react-native/framework-integrations#install-langchain-in-the-host-app).
The host owns frameworks, Babel and any URL/decoder/randomness polyfills.
Latchway does not install Firebase or LangChain. Reuse working host globals
and do not patch global fetch or add duplicate native randomness modules.

## 6. Create the Latchway client

Configure with public identity metadata through `Latchway.configure`. After
accepted application login, supply a current token through
`app.signIn({getIdToken})`, then `account.makeClient()`. If another native or
React Native caller is already signed in, attach with `app.makeClient()`.
Screen mount is not a new login; use `restore` for initial auth restoration.

## 7. Bind a feature

Each feature selects one protocol: Chat Completions, Responses, Embeddings,
Anthropic Messages or an allowed opaque route. Use its matching adapter and a
fetch bound to that feature. The gateway selects the provider/model and applies
quota; no upstream API key belongs in the client.

## 8. Create the framework client

```ts
import {createLatchwayChatOpenAI} from '@latchway/langchain';

const model = createLatchwayChatOpenAI({
  latchway: client,
  feature: 'assistant-chat',
  chatOptions: {maxTokens: 1024, maxRetries: 0},
});
```

Use `createLatchwayResponsesModel` for an `openai_responses` feature instead.
Generation options must fit the configured model and trusted accounting profile.

## 9. Send a non-streaming request

```ts
const result = await model.invoke('Help me plan tomorrow.', {
  signal: controller.signal,
});
```

Retain safe request IDs and complete messages. Do not log credentials or
request/response content as part of routine diagnostics.

## 10. Send a streaming request

```ts
for await (const chunk of await model.stream('Explain the plan.', {
  signal: controller.signal,
})) {
  // Render incremental text only while the captured account is still current.
}
```

Consume incrementally with bounded history. Do not store partial turns as
complete replay history.

## 11. Use tools

Follow [Chat tools](/clients/react-native/framework-integrations#chat-function-tools-and-quotas).
Validate tool names and arguments, authorize side effects, bound rounds/time/
result size, and append complete correlated assistant/tool messages only.
Every model round consumes quota, including schema and replayed history.
Latchway transports tools; it does not execute them.

## 12. Use structured output

Use strict schema output only with a compatible Responses route and model.
A framework exposing an API does not guarantee every server protocol accepts
it. Unsupported media, remote state or hosted tools must not bypass accounting.

## 13. Handle cancellation

Pass an `AbortSignal` to each model operation. Abort on user cancel, account
change and teardown. Also stop application tool work and discard old-generation
UI callbacks. Cancellation is not permission to replay an uncertain dispatch.

## 14. Handle quota failures

Show the stable error code and safe request ID and read authoritative quota
from the gateway. Limits belong to the configured user/feature scope; native
and React Native callers do not get separate allowances. Logout does not reset
the server's quota.

## 15. Handle session renewal

Native code coordinates session refresh. The application supplies fresh
external ID tokens with `account.updateIdToken`; the gateway verifies them for
the same durable account. `identity_refresh_required` suspends protected work
until a valid update. Logout is shared by native and React Native and works
offline; screen disposal is not logout.

## 16. Known limitations

Browser middleware, Node filesystem APIs, service workers, Realtime, uploads,
audio, image accounting and streaming request bodies are not inferred from a
working custom-fetch path. React Native extension behavior is a separate
capability. Package availability is not Apple distribution or Play-distributed
physical acceptance.

## 17. Verify the integration

Test raw fetch and each selected framework on both native hosts: non-streaming,
streaming, cancellation, renewal, account switching, quota failure, complete
tool loops and credential isolation. Check the Console's native host and caller
attribution without exposing tokens, proofs or content.

## 18. Troubleshooting

Confirm exact dependency locks, required host signing, the matching feature
protocol, and the app's token-refresh notifications. Fix incomplete runtime
capabilities at the application entrypoint; never widen destination allowlists
or disable attestation to hide integration errors.
