---
title: "React Native framework integration"
description: "Evaluate the experimental native-backed fetch for JavaScript AI frameworks without moving keys or session credentials into JavaScript."
---

<Warning>
  The React Native source candidate exposes a native-backed fetch-shaped API,
  but named framework compatibility remains pre-release and Installation Family
  component support has not passed release conformance.
</Warning>

## 1. What this integration does

The transport gives JavaScript safe response data and stream events while the
iOS or Android bridge owns key storage, refresh state, DPoP signing, attestation,
authenticated dispatch, and origin checks.

## 2. Supported framework versions

React Native `0.82.0` has an `experimental` native-backed-fetch row based on
bounded local tests and a supplemental development-signed physical iOS 27 run.
That run passed App Attest registration and same-key assertion, Secure Enclave
DPoP, upstream non-streaming and streaming requests, quota, typed component
denial, bridge behavior, and cleanup against the current source gateway. It is
not a published supported integration, and the named JavaScript framework rows
do not automatically apply to React Native.

## 3. Supported Latchway versions

The source candidate targets draft contract `1.0.0` and current protocol `2`;
protocol `1` remains accepted for compatible legacy routes. Installation
Family and Client Component operations are included in the draft wire-2
contract.

## 4. Security level

| Capability | Target and current status |
| --- | --- |
| Full DPoP preserved | Partial cross-platform evidence; Secure Enclave DPoP passed on physical iOS, while Android remains unproven |
| Private key remains native | Partial cross-platform evidence; physical iOS and local bridge isolation pass, while Android remains unproven |
| Streaming | Native pull streaming passes local gates and a physical iOS upstream run; Android remains unproven |
| Cancellation | Native cancellation passes local gates |
| App extensions | Not provided by the React Native framework-fetch integration |
| Structured output | Framework-specific evidence pending |
| Tool calls | Framework-specific evidence pending |
| Protocol | Draft contract `1.0.0`, current wire protocol `2`; legacy wire `1` remains accepted where compatible |

## 5. Install packages

`@latchway/react-native` version `1.0.0` is not published. Use only the pinned
source candidate and example for evaluation.

## 6. Create the Latchway client

Follow [React Native](/mobile/react-native). Native modules must receive the
platform configuration and identity callback without returning reusable
credentials to JavaScript.

## 7. Bind a feature

The source `fetchFor` surface binds one feature. Its signature remains
pre-release rather than a published contract.

## 8. Create the framework client

Pass the native-backed fetch only through a framework's supported request-time
transport seam. A static API key or static header path is insufficient.

## 9. Send a non-streaming request

The bridge returns safe status, headers, and bytes while native code owns
authorization. A request body already buffered within the 8 MiB bridge limit
may receive one exact pre-dispatch retry; a streaming or otherwise
non-replayable body is never retried.

## 10. Send a streaming request

The local bridge gates preserve incremental pull events and cancellation
without exposing session material or buffering the complete response.

## 11. Use tools

Tools remain framework concepts. JavaScript executes them; Latchway only
transports permitted protocol content.

## 12. Use structured output

Support is framework- and runtime-specific and requires an explicit conformance
row.

## 13. Handle cancellation

Abort cancellation reaches native dispatch in local tests and does not authorize
an automatic replay.

## 14. Handle quota failures

Surface the canonical problem and safe request ID across the native bridge.

## 15. Handle session renewal

Native modules single-flight refresh and generate a fresh proof for a permitted
pre-dispatch retry. JavaScript never reads the refresh credential.

## 16. Known limitations

Browser-only streams, uploads, or framework hooks may not exist in React
Native. The physical iOS observation used automatic Apple Development signing,
not an Apple distribution-derived protected immutable candidate. Android and
delegated-extension runtime evidence remain open.

## 17. Verify the integration

Test raw fetch and each named framework separately on both iOS and Android,
including streaming, cancellation, refresh, quotas, and credential isolation.

## 18. Troubleshooting

Check native diagnostics, runtime support, and exact dependency versions. Do not
log bridge payloads that can contain application request bodies.

## 19. Compatibility matrix

No supported named-framework row is published. See
[Compatibility](/reference/compatibility).
