Architecture Decision Records (ADRs) preserve the context, alternatives,
consequences, security effects, migration effects, documentation effects, and
status of durable technical choices.

The canonical records live in the core repository's
[`docs/adr/` directory](https://github.com/Latchway/latchway/tree/main/docs/adr).
This public page is an index and contribution guide, not a copied second
history.

## When an ADR is required

Write or amend an ADR for a change that alters a security boundary, normative
contract, durable data model, compatibility promise, release gate, extension
model, operational dependency, or accepted residual risk. Routine refactoring
that preserves those decisions normally belongs in a pull request only.

## Proposal structure

Use the next available four-digit number and include:

```text
Title
Context
Decision
Alternatives
Consequences
Security implications
Migration implications
Documentation implications
Status
```

Link the implementation and tests from the pull request. Do not place secret,
private incident, credential, exploit, or production-derived evidence in a
public ADR.

Accepted history is not silently rewritten. A later decision supersedes an
older record and links both directions. Renumbering requires an explicit note
that preserves historical identity and rationale.

## Review

Maintainers seek consensus. Security-sensitive records require security
review, compatibility changes require every affected repository owner, and
release-boundary changes require release-maintainer review. Acceptance of an
ADR records a decision; it does not itself prove implementation, deployment,
or release readiness.
