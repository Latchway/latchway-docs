---
title: "React Native"
description: "Integrate the Latchway React Native SDK with native App Attest and Play Integrity bridges."
---

`@latchway/react-native` exposes one fetch-shaped API while native iOS and
Android modules own installation keys, DPoP signing, rotating session state,
and platform attestation.

## Requirements

- React Native 0.82.x with the New Architecture enabled
- iOS 15 or newer with an App Attest-capable application entitlement
- Android API 24 or newer with Play Integrity configured
- a version-compatible Latchway gateway and SDK source set

The intended `1.0.0` package has not been published. For evaluation, use the
[React Native source repository](https://github.com/Latchway/latchway-react-native-sdk)
and its example application. Do not substitute an unverified registry package.

## Create a client

```typescript
import { createLatchwayClient } from "@latchway/react-native";

const latchway = createLatchwayClient({
  baseURL: "https://gateway.example.com",
  applicationID: "app_01J00000000000000000000000",
  environment: "production",
  getIdentityToken: async () => {
    const token = await applicationIdentity.currentToken();
    if (token === undefined) {
      throw new Error("The user must sign in before calling Latchway.");
    }
    return token;
  },
  android: {
    playIntegrityCloudProjectNumber: applicationConfiguration.googleCloudProjectNumber,
  },
});

const response = await latchway.fetch("/v1/chat/completions", {
  method: "POST",
  latchwayFeature: "habit_assistant",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({
    model: "assistant-default",
    messages: [{ role: "user", content: "Plan tomorrow" }],
  }),
});
```

`applicationID` is generated by the Admin API. A package name, bundle ID,
display name, or slug is not interchangeable with it.

## Lifecycle and replay behavior

Call `dispose()` when the owning application scope is destroyed. Secure
installation state remains available to later instances. `refresh()` rotates
session credentials explicitly; `revokeCurrentInstallation()` destroys the
server installation and local secure state.

Requests with bodies are never cloned or automatically replayed. Bodyless
requests receive at most one pre-dispatch retry for an exact canonical
`session_expired` or `dpop_nonce_required` response. Redirects and cross-origin
authorization are rejected.

## Production attestation

React Native delegates to the native SDKs:

- iOS uses an App Attest entitlement and a supported physical device.
- Android uses the configured cloud project and an exact signed application
  installed through the configured Google Play track.

Simulator, emulator, fixture, and sideloaded-debug success are development
signals only. See [Security boundary](/concepts/security-boundary).
