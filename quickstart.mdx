## Two distinct stages

<Tabs>
  <Tab title="Local source evaluation">
    <Badge color="blue">Local</Badge>

    Use Docker Compose, PostgreSQL, deterministic identity and upstream
    fixtures, signed debug evidence owned by the verifier, and a temporary
    schema. This proves the source path without third-party accounts.
  </Tab>
  <Tab title="Production hardening">
    <Badge color="green">Production</Badge>

    Configure real identity, production attestation or browser-risk policy,
    TLS, exact origins, upstream credentials, immutable routes and limits,
    operational jobs, backups, and release evidence.
  </Tab>
</Tabs>

<Warning>
  A passing local verifier does not prove App Attest, Play Integrity, browser
  integrity, live-provider behavior, a cloud deployment, or a published SDK.
</Warning>

Continue with the [operator quickstart](/operate/quickstart), then choose a
client journey after the gateway has an application resource ID, environment,
feature, and compatible trust policy.
