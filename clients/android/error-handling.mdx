## Capture only safe context

Control operations throw `LatchwayException`. It preserves `code`, safe
`message`, `title`, `httpStatus`, `requestId`, `documentationUrl`, and `retryable`.
Optional `retryAfter` is an RFC 3339 reset timestamp; `retryAfterSeconds` holds a
valid numeric Retry-After header. Missing timing remains absent.

Use `feature`, `errors` (`path`/`message`), `supportedProtocolVersions`, and
`operationId` when supplied. `instance` is an opaque correlation reference;
do not automatically follow it. Display the safe message and request ID, but
branch on `code`. Exception `toString()` omits diagnostic content.

Never log identity or session tokens, DPoP proofs, Android Keystore material,
Play Integrity tokens or verdict payloads, cookies, provider headers, or
response bodies containing application content.

## Decode an OkHttp failure

Protected HTTP calls preserve ordinary OkHttp response semantics. Use the
extension when your application needs a typed error:

```kotlin
import dev.latchway.okhttp.latchwayException

http.newCall(request).execute().use { response ->
    response.latchwayException()?.let { throw it }
    // Consume the successful response with your existing parser or framework.
}
```

The helper returns null for success without reading it. It peeks at a bounded
error body without consuming the original response. Invalid, oversized or
unreadable failures become `RESPONSE_INVALID`, preserving safe request
correlation and HTTP status. Custom transports can use
`LatchwayException.fromResponse(LatchwayTransportResponse(...))` with the same
canonical validation. Unknown optional extensions are ignored; required fields
and known optional fields remain validated.

## Diagnose by boundary

| Boundary | Confirm | Safe remediation |
| --- | --- | --- |
| Identity | Signed-in user and current issuer token | Reauthenticate the user; do not weaken integrity |
| Key storage | Keystore availability and policy-approved backing | Correct device or policy; never export the key |
| Play Integrity | Project, package, installed certificate, track, freshness, and verdict | Correct distribution or policy; do not retry permanent failures |
| Session/DPoP | Exact canonical code, request ID, nonce, and replayability | Allow only the native adapter's bounded pre-dispatch recovery |
| Destination | Exact HTTPS gateway origin and safe path | Remove redirects or arbitrary proxy targets |
| Quota | Effective limit plan and reservation | Show the policy result; do not maintain an authoritative client counter |
| Upstream | Request and attempt metadata | Follow route policy; do not add a provider credential to the app |

## Apply the right recovery

Server 1.1.4 reports requests that cannot fit a fixed limit as nonretryable
`request_invalid`. Reduce their size or requested output. A replenishable quota
still reports `quota_exceeded`; honor `retryAfter` when present. Validation
`errors` can identify `quota.<metric>` and its configured maximum.

Play Integrity guidance appears in the existing `errors` list, for example
`attestation.android_certificate_rejected`,
`attestation.android_testing_response_rejected`, or
`attestation.android_license_rejected`. Correct the installed build, distribution,
tester account or gateway policy. Testing responses still require an explicitly
allowed development environment. For `attestation_stale`, generate fresh
evidence for a new challenge. No client bypass is introduced.

The SDK owns HTTP transport, not provider SSE parsing. Read failures and
cancellation propagate; your parser/framework must reject explicit failed or
incomplete events and require its completion marker. HTTP 200 and partial output
are not completion. Never automatically replay a partial or dispatch-uncertain
request: `retryable` does not establish that replay is safe.

## Follow the stable page

Use [Error reference](/reference/errors) or the exception's
`documentationUrl`. `operation_indeterminate` requires reconciliation by
operation ID before the product offers another mutating action.

## Escalate

Provide safe resource IDs, package and version code, installed certificate
digest, track, OS/API level, SDK/server/contract tuple, request or operation ID,
component kind, and documentation URL. Exclude all credentials and raw verdict
material.
