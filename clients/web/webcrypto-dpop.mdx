The browser SDK generates an ECDSA P-256 key with `extractable: false`, stores
the CryptoKey object in origin-scoped IndexedDB, and gives the server only its
public JWK and RFC 7638 thumbprint. Every protected request has a fresh RFC
9449 DPoP proof for the exact method, URI, and access-token hash.

```text
non-exportable CryptoKey -> public JWK thumbprint -> bound session
          |
          +-> fresh proof(method, URI, token, jti) -> protected request
```

The SDK rejects caller-supplied credential-like headers and query names before
identity, session, or network work. It rejects authenticated redirects and a
custom Fetch result whose final origin differs from the configured gateway.

## Trust lifetime

The access token is short-lived. Refresh rotates a one-time token under a fresh
DPoP proof. Identity reauthentication or attestation step-up clears the old
session and starts a new challenge. Revoking the component or Installation
Family invalidates its server state; clearing browser storage creates new local
key material but does not itself delete the former server component.
