The default browser setting is `persistence: { mode: "required" }`.

| State | Location | Protection boundary |
| --- | --- | --- |
| Non-exportable P-256 private CryptoKey | IndexedDB | Raw key material cannot normally be exported; same-origin code may invoke it |
| Public JWK and thumbprint | IndexedDB | Public identifiers |
| Short-lived access and rotating refresh tokens | IndexedDB | Origin storage; intentionally not encrypted with a same-origin-accessible key |
| Concurrent request state | Memory | Cleared with the page or worker runtime |
| Cross-tab refresh lease | IndexedDB | Serializes rotating-token use for one database scope |

The SDK never uses localStorage, cookies, URLs, logs, or error messages for
session state. Encrypting IndexedDB tokens with a key available to the same
JavaScript origin would not stop an XSS attacker that can invoke decryption.

`allow-memory` explicitly permits a session-only fallback when IndexedDB or
CryptoKey cloning fails. `memory` intentionally skips persistence for
controlled tests. Neither mode is silently selected.

Clearing site data removes the local component key and session. The next use
creates a new browser component. The former server component remains until
expiry, cleanup, or revocation, so operators may temporarily see both. Private
browsing or storage denial can create the same continuity loss.
