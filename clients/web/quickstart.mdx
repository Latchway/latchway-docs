**Expected time:** 15 minutes with PostgreSQL and both source checkouts ready.

**Mode:** Local foreground development environment; production trust remains a
separate stage.

**Coordinates:** server contract `1.0.0`; JavaScript SDK source `1.0.0`.

## Outcome

Build a vanilla TypeScript client that authenticates an application user,
creates a WebCrypto-bound Latchway session, sends a request for
`habit-assistant`, and consumes its response with `ReadableStream`.

## Before you start

- a core checkout that passed the [operator quickstart](/operate/quickstart)
- a PostgreSQL URL whose role may create and drop an isolated schema
- ports 8080 and 5173 available on loopback
- Node 24.19, pnpm 10.15, and authorized `latchway-js` source

<Info>
  `latchway develop` owns the sample tenant, mock identity and upstream,
  challenge-bound debug signer, gateway, Admin API, and Console until you stop
  it. Its ephemeral schema and Console credential are cleaned up on exit.
</Info>

## What you will build

```text
Browser
  existing identity token + non-exportable WebCrypto P-256 key
  + challenge-bound development evidence from a trusted local helper
        |
        v
feature-bound Fetch -> Latchway -> configured development upstream
```

## Procedure

<Steps>
  <Step title="Start the foreground development environment">
    Build the core CLI, keep the terminal private, and start the exact loopback
    environment. The command prints its random Console password once.

```bash
cd ../latchway
go build -trimpath -o ./bin/latchway ./cmd/latchway
export LATCHWAY_DATABASE_URL='postgres://latchway:latchway-local-development@127.0.0.1:5432/latchway?sslmode=disable'
./bin/latchway --output json develop \
  --listen 127.0.0.1:8080 \
  --browser-origin http://localhost:5173
```

    Expected result: one `state: ready` document names `gateway_url`,
    `application_id`, `development`, `habit-assistant`, `assistant_default`,
    both helper URLs, and the Console credential. Diagnostic: if readiness does
    not print, verify the database role and port, then run the isolated verifier
    from the operator quickstart. Do not copy `console_password` into source,
    shell history, or a bug report.
  </Step>
  <Step title="Build and install the source package">
    Build the exact SDK checkout, create a local package archive, and install
    that archive in the Vite application.

```bash
cd ../latchway-js
corepack pnpm install --frozen-lockfile
corepack pnpm build
corepack pnpm pack --pack-destination ../web-app/vendor
cd ../web-app
corepack pnpm add ./vendor/latchway-client-1.0.0.tgz
```

    Expected result: `package.json` resolves `@latchway/client` 1.0.0 from the
    local archive. Diagnostic: run `corepack pnpm examples:check` in the SDK
    checkout to detect source-example drift.
  </Step>
  <Step title="Connect the server-owned development helpers">
    Add the tested helper module. It accepts only one exact loopback origin,
    omits credentials, rejects redirects and oversized responses, and sends the
    challenge ID, binding hash, DPoP thumbprint, platform, and deployment
    coordinates back to the signer that owns the matching private key.

    <WebDevelopmentHelper />

    Expected result: `getIdentityToken()` uses only
    `/development/v1/identity-token`; `getDevelopmentEvidence(context)` uses
    only `/development/v1/attestation-evidence`. Diagnostic: HTTP 403 means the
    exact browser origin or active challenge binding did not match; do not add a
    signing key to browser code.
  </Step>
  <Step title="Create the client and safe diagnostics">
    Add `src/latchway.ts` from the tested client module, then compose it with
    the helpers using the ready document's `gateway_url` and `application_id`.

    <WebDevelopmentClient />

```ts
const helpers = createLoopbackDevelopmentHelpers({
  baseURL: "http://127.0.0.1:8080",
});
const latchway = createLoopbackDevelopmentBrowserClient({
  baseURL: "http://127.0.0.1:8080",
  applicationID: "app_...", // application_id from latchway develop
  appVersion: "1.0.0",
}, helpers);
```

    Expected result: construction performs no network request. Loopback HTTP is
    accepted only when both the client opts in and the exact browser origin is
    allowlisted by an environment whose kind is `development`. After a session
    exists, `safeBrowserDiagnostics(latchway)` returns only allowlisted
    request-correlation, version, platform, persistence, and clock fields.
    Diagnostic: run `corepack pnpm exec tsc --noEmit` in the Vite application;
    do not substitute a browser-held debug signing key for the missing helper.
  </Step>
  <Step title="Bind the feature, send, and stream the response">
    Add `src/habit-assistant.ts`. Call `streamHabitAssistant(latchway, input,
    controller.signal)` from application code after constructing the client.

    <WebStreamingFetch />

    Expected result: callers cannot change the feature through a destination
    URL or provider header. Chunks remain browser Fetch data; Latchway does not
    buffer the response. Abort the supplied controller to cancel the request.
    Diagnostic: run `corepack pnpm build` in the Vite application and retain the
    safe response request ID if runtime policy rejects the call.
  </Step>
  <Step title="Verify in the Console">
    Open `console_url`, sign in with the printed one-run email and password,
    then correlate `requestID` under **Requests** and inspect the accepted trust,
    feature, selected route, attempts, and metered usage. Prompt bodies and
    identity subjects are not present by default.

    Expected result: one browser request row has the same request ID and the
    fields in the Verification section below. Diagnostic: with an authenticated
    CLI, run `latchway requests list --environment env_...` if the Console
    cannot load.
  </Step>
</Steps>

## Troubleshooting

<AccordionGroup>
  <Accordion title="IndexedDB or CryptoKey persistence is unavailable">
    The default `required` policy fails closed. Fix browser storage policy. Use
    `allow-memory` only after accepting that navigation creates new local state.
  </Accordion>
  <Accordion title="The development evidence helper rejects the challenge">
    Confirm that it signs only the active server challenge for the correct
    application, environment, DPoP thumbprint, and short expiry. Never copy its
    private key into the application bundle.
  </Accordion>
  <Accordion title="The protected request is redirected">
    Configure the final exact gateway origin. Authenticated requests use
    `redirect: "error"`; cross-origin authorization fails closed.
  </Accordion>
</AccordionGroup>

<Prompt title="Integrate Latchway Web source candidate 1.0.0">
Use @latchway/client 1.0.0 from the audited local archive with server 1.0.0.
Keep the existing identity provider, use a feature-bound fetch, require
