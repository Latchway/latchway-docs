Internal session and control operations throw `LatchwayError`. Protected Fetch
requests retain normal Fetch semantics and return final non-2xx responses. Map
one explicitly when application code needs the stable problem:

```typescript
import { errorFromResponse } from "@latchway/client";

if (!response.ok) {
  throw await errorFromResponse(response);
}
```

Catch `LatchwayError` and display its safe `message` with `requestID`, instead of
only its generic error name. It preserves `code`, `title`, `status`,
`documentationURL`, `retryable`, optional RFC 3339 `retryAfter`, `feature`,
`validationErrors` (`path`/`message`), `supportedProtocolVersions`, `operationID`,
and `instance`. Treat the instance as an opaque reference, not a URL to follow.

Version 1.1.1 ignores unknown optional extensions while validating required and
known optional fields. A malformed body becomes `protocol_response_invalid`
with safe HTTP status and header correlation; raw HTML/provider text is not used
as the fallback message.

| Browser symptom | Stable code | Direct action |
| --- | --- | --- |
| IndexedDB or CryptoKey cloning is unavailable | `storage_unavailable` | [Review persistent storage](#storage-unavailable) |
| The configured origin or HTTP policy is unsafe | `client_configuration_invalid` | [Correct client configuration](#client-configuration-invalid) |
| The browser cannot safely replay a consumed body | `transport_request_not_replayable` | [Create a new request](/reference/errors#transport_request_not_replayable) |
| The identity session is no longer acceptable | `identity_reauthentication_required` | [Reauthenticate the user](/reference/errors#identity_reauthentication_required) |
| Browser evidence is missing or wrong | `attestation_invalid` | [Create fresh challenge evidence](/reference/errors#attestation_invalid) |
| A quota reservation is denied | `quota_exceeded` | [Inspect the authoritative limit](/reference/errors#quota_exceeded) |

Never branch on the human `detail` string. Use `code`, status, retryability,
request ID, and documented safe fields. A `retryable: true` value does not
authorize replay after ambiguous upstream dispatch.

## Fixed limits and incomplete streams

Server 1.1.4 distinguishes a request that cannot fit a fixed limit
(`request_invalid`, not retryable) from an exhausted replenishable allowance
(`quota_exceeded`). Reduce the first request; honor a supplied `retryAfter` for
the second. `validationErrors` can identify `quota.<metric>` and its configured
maximum. The server remains authoritative for usage.

The gateway aborts failed partial responses. Custom SSE parsers must reject
failed/incomplete events and require their provider's completion marker; HTTP
200 or partial text alone is insufficient. Keep the request ID and do not
automatically replay after output starts or dispatch becomes uncertain.

Native App Attest and Play Integrity reasons are not Web trust. Browser App
Check or Turnstile errors still require their own challenge/evidence recovery;
never infer hardware attestation from WebCrypto key possession.

See the [complete generated error registry](/reference/errors), generated from
`api/error-codes.yaml`. Include the code, request ID and version tuple for support;
never log identity/session tokens, DPoP proofs or application response bodies.

## Browser-local diagnostic links

### storage-unavailable

The required IndexedDB or CryptoKey-cloning boundary is unavailable. Restore
browser storage or explicitly accept session-only `allow-memory` behavior.

### client-configuration-invalid

Correct the exact URL, HTTPS policy, application ID, environment, identity
callback, persistence mode, or attestation-provider configuration before retrying.
