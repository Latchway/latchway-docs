The Swift SDK keeps the component key, App Attest state, rotating refresh
state, and request-time DPoP proof in native code. The application keeps its
existing identity provider and requests a configured feature rather than a
physical provider model.

## Request path

```text
existing identity -> App Attest-aware session -> component DPoP -> feature policy -> upstream
```

- [Authentication](/clients/ios/authentication) covers the existing user token
  and reauthentication boundary.
- [Send a request](/clients/ios/send-a-request) covers feature binding and
  destination restrictions.
- [Streaming](/clients/ios/streaming) covers incremental delivery,
  cancellation, and retry safety.
- [Framework integrations](/clients/ios/framework-integrations) routes to the
  tested Foundation Models and SwiftOpenAI adapters.
- [App extensions](/clients/ios/app-extensions) explains delegated component
  trust without describing an extension as directly attested.
- [Error handling](/clients/ios/error-handling) preserves stable error and
  request identifiers without logging credentials.

## Support boundary

The source candidate supports iOS 15 or newer and Swift 6. Its intended public
package and CocoaPods artifacts are not available until
[Release status](/release-status) records publication. Review the generated
[iOS SDK bundle](/reference/sdk-bundles/ios) for source-provenanced version and
symbol evidence.

<Warning>
  A simulator, fixture, source build, or Apple Development-signed run is not a
  protected distribution receipt. Production App Attest evidence must come
  from the exact signed application and immutable gateway candidate under test.
</Warning>
