## Outcome

The application builds against the intended `Latchway` and
`LatchwayAppAttest` products, and its signed entitlements expose the exact
private Keychain group and App Attest capability expected by configuration.

## Select the package source

Add the published repository version in Xcode or the application package manifest:

```swift
.package(url: "https://github.com/Latchway/latchway-ios-sdk.git", exact: "2.0.0")
```

Link `Latchway` and `LatchwayAppAttest` to the main application target. Supply
ID tokens from the application's existing identity provider; the core needs no
Firebase dependency or authentication bootstrap.
Add `LatchwayAppExtensions` only to targets that execute the delegated
component flow.

For a CocoaPods host:

```ruby
pod 'Latchway/AppAttest', '2.0.0'
```

For an existing CocoaPods installation, update the declared version and run
`bundle exec pod update Latchway --repo-update` (omit `bundle exec` if unused).
An ordinary `pod install` preserves the older locked version. Keep this update
scoped to Latchway rather than upgrading unrelated pods.

The optional Foundation Models product/subspec requires OS 27 and server 1.0.2+
for expanded generation requests. See the versioned
[Foundation Models guide](https://github.com/Latchway/latchway-ios-sdk/blob/v2.0.0/Documentation/FoundationModels.md).
React Native 2.0.0 pins this same iOS version. Use one native SDK copy when
embedding React Native, not independent CocoaPods and SwiftPM implementations.

Version 2 removes legacy constructors, callback authorities and migration/adoption
APIs. Old SDK storage is not migrated automatically. Retained Keychain data is
not proof of a valid current account; reinstalling the app does not guarantee
Keychain erasure. See [release boundaries](/release-status#upgrade-and-rollback).

## Resolve signed capabilities

1. Enable App Attest on the exact application identifier.
2. keep the root application's private app-ID Keychain group first.
3. add extension-shared groups only when an extension requires them.
4. pass the fully resolved group such as `ABCDE12345.com.example.app`; do not
   pass `$(AppIdentifierPrefix)` at runtime.
5. keep private keys and refresh state non-synchronizable.

Inspect the built application rather than the unresolved project file:

```bash
codesign -d --entitlements :- /path/to/LatchwayConsumer.app
```

Expected result: the App Attest entitlement is present and the first
`keychain-access-groups` value is the private root group supplied to the SDK.

## Verify the package

From the SDK checkout:

```bash
swift test
```

Then compile the application target. A passing package build establishes source
and toolchain compatibility; it does not establish device attestation or
distribution status.
