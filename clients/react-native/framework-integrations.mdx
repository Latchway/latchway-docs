## Outcome

A tested framework consumes `fetchFor(feature)` while native modules retain
DPoP, attestation, session state, destination validation, and response
streaming.

## Start from generated evidence

For a current LangChain application, use the release-line setup below and check
[Release status](/release-status) for publication. Generated
framework tables retain their historical conformance coordinates; they are not
evidence of fresh physical-device testing for these package versions.

Use [React Native framework integration](/integrations/react-native) and the
generated [Compatibility matrix](/reference/compatibility) for exact package
versions and covered capabilities. The source candidate includes consumers for
selected OpenAI JavaScript, Vercel AI, LangChain JavaScript, and Anthropic
Messages paths.

This is not a blanket claim for every API in those packages. Browser-only
middleware, Node filesystem dependencies, service workers, Realtime, uploads,
audio, images, streaming request bodies, or framework paths without a custom
fetch seam remain outside the tested surface.

## Install LangChain in the host app

```bash
npm install --save-exact @latchway/react-native@2.0.0 @latchway/langchain@1.1.0 \
  @latchway/client@1.1.0 @langchain/core@1.2.9 @langchain/openai@1.5.10 openai@7.8.0
```

The base SDK does not depend on LangChain, Babel helpers or global URL/decoder
polyfills. Follow the versioned
[runtime and Babel guide](https://github.com/Latchway/latchway-react-native-sdk/blob/main/docs/langchain.md)
and copy its application-owned bootstrap before importing frameworks. Reuse
complete globals already supplied by the host; do not install duplicate native
randomness modules or replace global fetch. Recopy old bootstrap files when
upgrading: npm cannot update copies in application source.

React Native's partial URL implementation can add a trailing slash to an API
path. Version 1.1.2 checks exact Chat Completions and Responses paths and preserves
working host implementations. Never widen the SDK destination allowlist to hide
`transport_destination_not_allowed`.

## Create a Chat Completions model

Configure with the public coordinates in the
[quickstart](/clients/react-native/quickstart). After an accepted application
login, supply a current ID token and pass the resulting client directly:

```ts
import {createLatchwayChatOpenAI} from '@latchway/langchain';

const account = await app.signIn({getIdToken: () => yourAuth.getIdToken()});
const latchway = await account.makeClient();
const model = createLatchwayChatOpenAI({
  latchway,
  feature: 'assistant-chat',
  chatOptions: {maxTokens: 1024, maxRetries: 0},
});
const controller = new AbortController();
for await (const chunk of await model.stream('Help me plan tomorrow.', {
  signal: controller.signal,
})) {
  // Render incremental text without storing credentials or incomplete history.
}
```

The feature must select `openai_chat`. For an `openai_responses` feature use
`createLatchwayResponsesModel` on server 1.0.2+, with model-appropriate generation
options and accounting. The server chooses the physical model; no upstream key
belongs in either constructor. Defaults disable framework retries; preserve
cancellation and never replay an uncertain dispatch automatically.

If native or another React Native surface already signed in, use
`await app.makeClient()` without another sign-in. Screen mount does not imply
login. For application-auth restoration, use `app.restore({getIdToken})`.
The provider and token getter are application-owned; no Firebase package or
native authentication bootstrap is required by Latchway.

Scope the client and in-memory history to the captured account and environment.
Push fresh tokens with `account.updateIdToken({getIdToken})`; at expiry,
`identity_refresh_required` suspends protected work until a verified update.
On account change, abort streams and tool execution, ignore stale callbacks,
clear history and dispose the old client. Current-account logout uses `app.signOut()` and
affects native and React Native without resetting user quotas. Serialize
external-provider login/logout calls in your app. See
[authentication](/clients/react-native/authentication) for lifecycle details.
Use the user's ID token, not a UID, App Check token,
custom sign-in token or service-account JSON. Read authoritative quota from the
server. Tool execution remains app-owned: validate arguments, enforce an
allowlist, bound the loop and append complete correlated tool results only.

## Chat function tools and quotas

Chat `bindTools` with input/total-token quotas requires **server 1.0.4+**.
Earlier versions reject these requests before provider dispatch. Updating the
React Native package or switching a Chat-only feature to the Responses API is
not the fix. Keep quotas and required native attestation enabled.

Use `bindLatchwayTools(model, tools)` from `@latchway/langchain` 1.1.0 with
ordinary local functions and strict object schemas. The helper supplies boolean
`strict: true` and `parallel_tool_calls: false` defaults. Keep
`useResponsesApi: false` for a Chat feature, `maxRetries: 0`, and an explicit
output cap. Unknown options such as `temperature` and `response_format` remain
outside this trusted Chat profile; this patch is not general structured-output
or hosted-tool support.

After a complete tool-call response, validate the function name and arguments,
authorize and execute it in app/backend code, and append the complete assistant
message plus a correlated `ToolMessage`. For streaming, assemble all deltas
before executing a tool; never execute partial arguments. Bound rounds, tool
count, execution time and result size. On cancellation or failure, discard the
incomplete turn, retain previous complete history, and do not retry silently.
Every model round consumes quota, including tool schemas and replayed history.

The server accepts up to 128 function definitions and 128 calls per assistant
message, within 4,096 combined framing units and 4 MiB of expanded schema
accounting. Local acyclic JSON-pointer references are supported; remote,
recursive, unresolved or scope-changing references fail closed. Media,
provider-hosted/custom tools and incomplete call/result exchanges are excluded.

## Bind each protocol separately

Create a separate feature for Responses, Chat Completions, Embeddings,
Anthropic Messages, or an allowed opaque route. One feature cannot represent
multiple protocol adapters. Give the framework a fetch permanently bound to
that feature and the canonical gateway origin.

Use a conspicuous non-secret placeholder only when a constructor requires an
API-key-shaped value. Native filtering must discard it. Disable
framework-owned retries and preserve `AbortSignal` plus incremental response
consumption.

## Verify
