<Badge color="red">Production checklist</Badge>

React Native release readiness requires two native proofs. Bind each result to
the exact JavaScript archive, iOS and Android artifacts, source commits,
contract, gateway image, active configuration, and signed application under
test.

## Shared package and bridge

- [ ] The selected React Native/React pair satisfies the supported peer ranges;
  New Architecture codegen, TypeScript, Metro bundles,
  clean packed consumer, and exact compatibility locks pass.
- [ ] Local native overrides are absent from published package metadata.
- [ ] Version 2 ships in a rebuilt native binary, not an OTA-only JavaScript
  update; no automatic migration of older SDK storage is assumed.
- [ ] JavaScript receives no private key, access or refresh token, DPoP proof,
  raw attestation evidence, or credential-bearing request.
- [ ] Native-first and React-Native-first configuration reuse one shared app,
  account and session; conflicting explicit configuration fails closed.
- [ ] The app supplies identity tokens, reports external-auth changes, refreshes
  before expiry and resumes `identity_refresh_required` only after verification.
- [ ] Shared offline logout fences old requests, tools and UI callbacks. Screen
  teardown only disposes the client. Restart restoration cannot undo logout.
- [ ] No Firebase dependency or native authentication bootstrap is required by
  Latchway; all existing application auth surfaces participate in the lifecycle.

## iOS proof

- [ ] The exact signed bundle, Team ID, App Attest entitlement, private root
  Keychain group, extension groups, and server policy agree.
- [ ] Real App Attest, native key storage, DPoP, streaming, cancellation,
  diagnostics, quota, revocation, and sign-out were exercised.
- [ ] Development-signed evidence is not reported as protected distribution
  evidence.

## Android proof

- [ ] The exact Play project, package, installed certificate, track, verdict
  policy, and native module graph agree.
- [ ] A Play-installed candidate proves Play Integrity, Keystore, DPoP,
  streaming, cancellation, diagnostics, quota, revocation, and sign-out.
- [ ] An emulator, fixture, sideloaded APK, or iOS result is not substituted.

## Transport and operations

- [ ] Every framework is feature-bound and listed in the generated
  compatibility matrix at its exact tested version.
- [ ] Framework retries are disabled; `AbortSignal`, backpressure, safe error
  mapping, and uncertain-operation reconciliation pass.
- [ ] Request views correlate platform, user, family, component, trust,
  feature, route, usage, and quota without exposing content or credentials.
- [ ] [Release status](/release-status) records npm and native dependency
  publication before installation instructions switch to registries.

Complete [Physical-device proof](/mobile/device-proof) for each platform before
rolling out your application. Published package availability does not complete
this application-specific checklist.
