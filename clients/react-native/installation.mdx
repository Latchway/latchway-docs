## Outcome

The application resolves `@latchway/react-native` and the exact reviewed iOS,
Android, JavaScript, contract, and gateway compatibility coordinates. Confirm
the package's publication in [Release status](/release-status) before installing
a newly prepared release; source validation alone is not a registry receipt.

## Meet the baseline

- React Native `>=0.74.0 <1.0.0` and React `^18.2.0 || ^19.0.0`, with the New
  Architecture enabled;
- iOS 15+ and the version-locked Latchway CocoaPods/Swift source;
- Android API 24+ and the version-locked `dev.latchway` source modules; and
- the repository-pinned Node, pnpm, CocoaPods, Gradle, Java, and Android
  toolchains used by the example.

These are supported peer ranges, not a claim that every future React Native
version has been tested. Use a compatible React/React Native pair from your
host application. Legacy Architecture and Expo-managed integration are not
claimed. The Android libraries compile against API 34; the host and other
dependencies may require a newer compile or target SDK.

## Install in an application

```bash
npm install --save-exact @latchway/react-native@2.0.0
cd ios
bundle exec pod install
cd ..
```

Use `pod install` if the host does not use Bundler. The npm podspec resolves
`Latchway/AppAttest` 2.0.0; Gradle resolves the locked `dev.latchway` 1.2.1
artifacts from Maven Central. Do not add local SDK paths or a second native
implementation. Rebuild the native app after installation; a JS reload is not enough.

When upgrading an existing host, `Podfile.lock` may still pin the older native
SDK. After updating npm, run `bundle exec pod update Latchway --repo-update`
from `ios` (or `pod update Latchway --repo-update` without Bundler). This unlocks
the Latchway pod specifically; ordinary `pod install` preserves the old lock and
can reject the new exact dependency. Do not update every unrelated pod.

Version 2 removes legacy migration, credential-adoption and callback-authority
APIs. It does not migrate old storage automatically. Do not ship this bridge
upgrade as an OTA-only JavaScript update.

The base SDK requires only `@latchway/client` 1.1.0 and a private stream fallback.
It does not install LangChain or initialize global runtime polyfills. For that
integration, follow [framework setup](/clients/react-native/framework-integrations)
before importing dependent libraries. There is no Firebase dependency or
Latchway-specific native bootstrap. Supply public identity metadata and a
current ID token from your application's existing authentication system.

## Standalone and embedded React Native

Both use `Latchway.configure`. Matching native and React Native configuration
joins the same process-wide app and account regardless of which side configured
first. Do not install another native SDK copy or create an extra authentication
owner for the React Native screen. Conflicting explicit configuration fails with
`configuration_conflict` instead of silently changing the shared app.

App Attest entitlements, the signed private root Keychain group and Play
Integrity configuration are still native host setup. An SDK cannot grant those
permissions from JavaScript. Follow [authentication](/clients/react-native/authentication)
for sign-in, token refresh and shared logout.

## Develop the SDK workspace

From the React Native SDK checkout:

```bash
corepack pnpm install --frozen-lockfile
cd example/ios && bundle exec pod install && cd ../..
```

The example contains local iOS and Android development overrides. Keep those
overrides in development configuration; published package metadata must resolve
the promoted native artifacts instead.

## Verify generation and consumers

```bash
corepack pnpm example:check
corepack pnpm example:bundle:check
corepack pnpm codegen:check
corepack pnpm consumer:check
```

Expected result: TypeScript, TurboModule generation, Metro bundles, native
host dependency checks, and a clean packed consumer agree with the source
locks. A passing bundle does not establish App Attest, Play Integrity, or
physical-device behavior.

Continue with [iOS native setup](/clients/react-native/ios-native-setup) and
[Android native setup](/clients/react-native/android-native-setup).
