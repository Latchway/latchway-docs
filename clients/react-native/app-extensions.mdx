## Outcome

An independently executing signed iOS extension can construct the separate
component client for redacted delegated-session diagnostics after the
containing app provisions its component key. The React Native JavaScript API
does not expose a component request operation. The example's Debug App Intent
instead calls the native extension client directly for one bounded delegated
request; it cannot use the root client or move root credentials through
JavaScript.

## Current version 1 boundary

- the current process must be an iOS `.appex`;
- the component descriptor contains only definition ID, kind, fully resolved
  shared Keychain group, and requested feature IDs;
- the extension owns an independent component key and delegated session;
- it has no root identity callback or App Attest provider;
- only redacted diagnostics cross the React Native bridge; and
- React Native version 1 exposes no JavaScript component request operation.

The example App Intents extension does not host a React Native runtime. In
Debug it links `Latchway/AppExtensions`, constructs a native
`LatchwayExtensionClient`, fully consumes one bounded Responses request, and
writes a nonsecret receipt bound to the containing app's current exact-run
Keychain challenge. In Release it has no Latchway dependency or executable
request path and fails closed. Local tests plus generic iOS and isolated
Debug/Release App Intent build gates prove the source boundary; the current
Debug intent has not yet been physically invoked.

<Warning>
  The containing application cannot attest on behalf of the extension. A
  delegated component is not directly attested, and the presence of a legacy
  direct-attestation symbol does not make that trust source available.
</Warning>

## Follow the native guides

Configure [iOS app-extension trust](/clients/ios/app-extensions), containing-app
provisioning, Keychain isolation, feature sealing, sign-out, and component
revocation in the native SDK. Do not copy root DPoP keys, refresh chains,
identity tokens, or App Attest evidence into the extension.

## Verify

Confirm diagnostics report the extension's independent component ID and key,
delegated provenance, sealed feature scope, and no root or credential fields.
For the Debug App Intent, also confirm that the exact-run receipt appears only
after the native delegated response body is fully consumed. Do not claim
physical extension execution until that intent runs on the exact signed source,
and do not treat Debug evidence as protected distribution evidence.
