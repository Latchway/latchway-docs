## Outcome

The React Native Android host resolves the locked native modules, configures
Play Integrity for the exact signed application, and keeps Keystore, DPoP,
refresh, integrity, and protected networking behind the TurboModule.

## Configure the host

1. install the npm package and let autolinking resolve its Maven dependencies;
2. compile against the supported host toolchain with New Architecture enabled;
3. set `android.playIntegrityCloudProjectNumber` to the decimal-string Cloud project number
   and `android.keyPolicy` to `hardware_backed_required`;
4. match the server policy's package, installed signing certificate, Play
   track, and verdict requirements; and
5. retain the locked Latchway interceptor, network origin guard, and
   authenticator supplied by the native bridge.

For shared native/RN mode, configure the gateway's native `android` host with
an explicit `sharedNativeCallers` policy admitting the intended callers,
required direct Play Integrity and the exact package name. Existing standalone
`android` / `react_native_android` root-pair policies remain compatible; an
upgrade does not merge them or widen permissions automatically. Use the Play
app-signing SHA-256, not merely the upload-key certificate; the server schema
stores its digest as Base64URL. Version bounds `0`/`0` allow all valid version
codes without weakening package, certificate, licensing or device verdict checks.

Keep the verifier service-account JSON in an encrypted server secret. It does
not belong in the mobile app. Supply public identity metadata and a current
user ID token from application-owned auth. Authentication is separate from
Play Integrity, and
Firebase App Check is not a replacement for this native policy.

No Firebase dependency or native Latchway authentication bootstrap is needed.
React Native calls `Latchway.configure`; equivalent Kotlin configuration before
or after it reuses the same app/account. The bridge resolves Android SDK 1.2.1.
Its libraries compile against API 34; your host's React Native version and
other dependencies can require a newer compile or target SDK.

Do not pass an integrity token, request hash, DPoP proof, private key, access
token, refresh token, or provider credential through JavaScript configuration.

## Verify source wiring

```bash
./android/gradlew -p example/android :app:compileDebugKotlin --no-daemon
corepack pnpm example:bundle:check
```

Then use a Play-installed signed application for the real verdict. Confirm the
request view reports host platform `android` and caller SDK `react-native`, the
expected user and feature, Play Integrity trust, DPoP verification and usage.
SDK diagnostics may report `react_native_android` and the native key-storage
category; that is distinct from the shared server host platform.

<Warning>
  An emulator or sideloaded APK tests host wiring only. It is not production
  Play Integrity evidence, and an iOS React Native result does not substitute
  for the Android gate.
</Warning>

For the Apple host, open [iOS native setup](/clients/react-native/ios-native-setup).
