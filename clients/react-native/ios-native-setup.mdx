## Outcome

The React Native iOS host loads the version-locked Swift SDK, signs for the
exact bundle identifier, and keeps App Attest, Secure Enclave or Keychain,
DPoP, and refresh state behind the native bridge.

## Configure the target

1. install the npm package and run CocoaPods in the host app;
2. enable the App Attest entitlement for the exact application identifier;
3. put the fully resolved private root app-ID Keychain group first in the
   signed entitlement;
4. add only explicit extension-shared groups after it;
5. set `apple.rootKeychainAccessGroup` to the resolved private group.

Version 2 has no legacy shared-group migration option. Native delegated
extensions use explicit current component groups; never put root credentials
in an extension-shared group.

Never pass `$(AppIdentifierPrefix)` at runtime. Inspect the built `.app`
entitlements rather than inferring expansion from the Xcode project.

Require App Attest and disallow software-key fallback for the protected root.
Match the App Attest entitlement and signing category to the selected environment.
For shared native/RN mode, configure the gateway's native `ios` host with an
explicit `sharedNativeCallers` policy admitting the intended callers and
required direct App Attest. Existing standalone `ios` / `react_native_ios`
root-pair policies remain compatible; upgrading does not merge them or widen
their permissions automatically.

No Firebase package, application-delegate authentication code or native
Latchway bootstrap is required for the supplied-identity API. React Native
calls `Latchway.configure` with the signed group and public identity metadata.
Native can configure before or after it with equivalent settings. If the host
uses Latchway natively, resolve the same iOS 2.0.0 SDK copy instead of linking
another version through Swift Package Manager and CocoaPods simultaneously.

## Keep the bridge narrow

The TypeScript layer may supply non-secret configuration and a current external
identity token. It must not supply or receive an App Attest challenge, raw
evidence, DPoP private key, access token, refresh token, or provider credential.

Native and React Native share the same process-wide account and security scope.
Conflicting explicit gateway, app name, application, environment, identity,
Keychain or trust configuration fails closed. Use `app.signOut()`
for sign-out; disposing a screen client does not log out native callers.

## Verify

Build the example workspace and run on the exact intended device. Confirm:

```text
Server host platform: ios
Caller SDK: react-native
Native key storage: reported
Trust provider: app_attest
DPoP: verified
JavaScript credential fields: absent
```

SDK diagnostics may report `react_native_ios`; shared server sessions use the
native host platform and record caller SDK separately.

A development-signed result is useful device evidence but remains distinct
from a protected Apple distribution receipt. Continue with the
[production checklist](/clients/react-native/production-checklist).

For the other host, open [Android native setup](/clients/react-native/android-native-setup).
