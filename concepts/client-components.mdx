A **Client Component** is one independently executing application surface. An
iOS containing app, Widget extension, Share extension, Android app process, Wear
OS companion, or browser installation can each be a component when a configured
Component Definition permits it.

Each component owns:

- one P-256 key and DPoP thumbprint;
- its own access sessions and rotating refresh-token chain;
- an explicit feature scope and component type;
- independent quota attribution and revocation state;
- trust provenance that says whether trust is direct or delegated.

The App Group or other shared store may carry non-secret provisioning material.
It must not contain a DPoP private key, access token, rotating refresh token, raw
attestation object, identity token, or upstream credential.

## Isolation invariants

A component credential cannot cross an Installation Family, application,
environment, component type, or application user. A component session is bound
to the component key that created it. Sign-out invalidates the family
credentials associated with the prior user.

## Root and delegated components

<TrustPath />

The root component establishes the family's primary trust. A delegated
component presents a short-lived, single-use authorization issued by the root
for that component's public key and definition. Read [Trust
provenance](/concepts/trust-provenance) before designing an extension flow.

Root definitions must match the unique required attestation selection for their
platform. App Attest roots pin its exact bundle identifier, Play Integrity
roots pin its exact package name, and browser roots partition every allowed web
Origin exactly once. Browser challenges persist that exact Origin, so an
exchange from a different allowed Origin cannot select another root. Native or
debug policies without a durable verified identifier permit only one root.

The `identity_only` root strategy remains reserved in the draft configuration
schema for compatibility, but version 1 rejects it during semantic validation
and compiled-snapshot loading. Configure direct root attestation instead; the
internal identity-only legacy bridge is not an activatable configuration
surface.
