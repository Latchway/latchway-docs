Latchway version 1 is an implementation source candidate. The core and four
SDK repositories build and pass their local conformance suites, but no public
version 1 release should be inferred from source version strings.

The current core binary identifies as `1.0.0-rc.1`. The intended stable server
and SDK versions are `1.0.0`; draft contract `1.0.0` selects wire protocol `2`
as current while retaining wire `1` for compatible legacy clients. Those
coordinates are release intent until protected promotion completes.

Promotion is evidence-driven. One exact candidate must pass protected live
provider, mobile device, cloud deployment, multi-replica failure, backup and
restore, upgrade, load, vulnerability, SBOM, signature, provenance, registry,
and cross-repository conformance gates. Local tests cannot manufacture those
receipts.

Image publication, release promotion, public-state observation, deployment
capture, and release-record finalization enforce a source/credential split:
their candidate source is evaluated in credential-free jobs, while registry,
GitHub, provider, and OIDC jobs accept bounded hash-verified handoffs without
checking out that source. Live JavaScript conformance remains fail-closed until
its identity and App Check or Turnstile proofs are delivered as single-use,
run-bound capabilities on a gateway-egress-only ephemeral runner. The split
closes specific workflow trust boundaries, but does not substitute for the
external receipts.

## What is usable now

Authorized evaluators can build the source checkouts, run the isolated local
verification suite, inspect the immutable control plane, integrate the mobile
SDK examples, and prepare protected release infrastructure. Supplemental local
container, multi-architecture, scan/SBOM, failure, recovery, and load work
exists, but it is bound to local checkpoints and does not establish a released
image.

A supplemental real-device run also passed the React Native iOS bridge, Apple
production App Attest registration and same-key assertion, Secure Enclave DPoP,
upstream non-streaming and streaming requests, quota, typed component denial,
and cleanup. It used React Native commit
`6de46e1c7264e1d45cdd31174e4ea040a8c24acf` in Debug configuration on an
iPad running iPadOS 26.5 with automatic Apple Development signing. It did not
use an Apple Distribution, ad hoc, TestFlight, or App Store candidate, so it
does not authorize release promotion.

Current React Native source
`2d78f588671d35512c6d0d244c89ec61e6a48cfa` materially adds root-owned
component descriptor lifecycle and a Debug App Intent that uses the native
extension client for one exact-run delegated request. Its full local check plus
generic iOS and isolated Debug/Release App Intent build gates pass, but the
intent has not yet been physically invoked. The Release App Intent target
contains no Latchway request path and fails closed. Neither source/build result
extends the historical physical proof or authorizes release promotion.

## What must remain gated

Do not advertise release-qualified Apple App Attest, Play Integrity,
immutable-image live-provider compatibility, cloud support, multi-replica
resilience, signed packages, or released package/image availability until the
matching external domain has an authenticated receipt for the exact candidate.
Missing credentials, devices, provider accounts, or registry access produce an
open gate, never a synthetic pass.

<Info>
  Until promotion completes, evaluate Latchway from repository-local tested
  source checkouts. This is not an independent security audit. Do not assume
  that `1.0.0` exists on a public package registry.
</Info>
