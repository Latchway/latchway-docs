---
title: "Release status"
description: "What the Latchway version 1 source candidate proves—and what remains externally gated."
---

Latchway version 1 is an implementation source candidate. The core and four
SDK repositories build and pass their local conformance suites, but no public
version 1 release should be inferred from source version strings.

| Area | Current claim |
| --- | --- |
| Core gateway and control plane | Implemented and locally validated |
| React Native, iOS, Android, and JavaScript SDK sources | Implemented and locally validated |
| Protocol contract | Pinned and checked across repositories |
| Public tags and immutable GitHub releases | Not yet promoted |
| npm, Swift/CocoaPods, and Maven publication | Not yet published |
| Production App Attest and Play Integrity | Requires protected physical-device evidence |
| Live upstream-provider evidence | Requires protected credentials and bounded runs |
| Cloud deployment and resilience evidence | Requires configured provider accounts |
| Image signing, provenance, and post-publication checks | Required before support claim |

Promotion is evidence-driven. One exact candidate must pass protected live
provider, mobile device, cloud deployment, multi-replica failure, backup and
restore, upgrade, load, vulnerability, SBOM, signature, provenance, registry,
and cross-repository conformance gates. Local tests cannot manufacture those
receipts.

<Info>
  Until promotion completes, evaluate Latchway from audited source checkouts.
  Do not assume that `1.0.0` exists on a public package registry.
</Info>
