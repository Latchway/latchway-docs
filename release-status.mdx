Promotion is evidence-driven. One exact candidate must pass protected live
provider, mobile device, cloud deployment, multi-replica failure, backup and
restore, upgrade, load, vulnerability, SBOM, signature, provenance, registry,
and cross-repository conformance gates. Local tests cannot manufacture those
receipts.

Local source testing covers the Go check, race, fuzz, and real PostgreSQL
suites; Console unit, build, and browser suites; and each SDK's release and
consumer gates. Independent review closed root-challenge and App Attest
post-disable insertion races, configuration and family/component lock-order
deadlocks, exact JSON/YAML numeric preservation, and explicit `READ COMMITTED`
lifecycle behavior. Those local results do not replace the final clean
cross-repository run or protected artifact evidence for the exact publication
candidate.

Image publication, release promotion, public-state observation, deployment
capture, and release-record finalization enforce a source/credential split:
their candidate source is evaluated in credential-free jobs, while registry,
GitHub, provider, and OIDC jobs accept bounded hash-verified handoffs without
checking out that source. Live JavaScript conformance remains fail-closed until
its identity and App Check or Turnstile proofs are delivered as single-use,
run-bound capabilities on a gateway-egress-only ephemeral runner. The split
closes specific workflow trust boundaries, but does not substitute for the
external receipts.

## What is usable now

Authorized evaluators can build the source checkouts, run the isolated local
verification suite, inspect the immutable control plane, integrate the mobile
SDK examples, and prepare protected release infrastructure. Supplemental local
container, multi-architecture, scan/SBOM, failure, recovery, and load work
exists, but it is bound to local checkpoints and does not establish a released
image.

A supplemental real-device run also passed the React Native iOS bridge, Apple
production App Attest registration and same-key assertion, Secure Enclave DPoP,
upstream non-streaming and streaming requests, quota, typed component denial,
and cleanup. It used React Native commit
`6de46e1c7264e1d45cdd31174e4ea040a8c24acf` in Debug configuration on an
iPad running iPadOS 26.5 with automatic Apple Development signing. It did not
use an Apple Distribution, ad hoc, TestFlight, or App Store candidate, so it
does not authorize release promotion.

React Native predecessor `4264b47e270f5e9c05938d8108eacb79c7bf4e99`
adds root-owned component descriptor lifecycle and a Debug App Intent that uses
the native extension client for one exact-run delegated request. Its Apple
Development root app and embedded App Intents extension passed strict
entitlement/provisioning, registered-device install, and launch checks. It did
not invoke the intent or collect new App Attest proof. Current
`39fd86ef1f6f973953e4fd5d0057ae17cc035abb` carries the release retry-closure,
transition-order, wording, and development-runner hardening, then locks the
released contract and final JavaScript, iOS, and Android successor commits. Its
local plus generic iOS and isolated Debug/Release App Intent build gates pass;
the physical path was not rerun at that head. The Release App Intent target
contains no Latchway request path and fails closed. None of these results
extends the historical live proof or authorizes release promotion.

## Current source and authorization boundary

Source-branch synchronization is a delivery operation and does not promote a
release. No merge, tag, GitHub release, package/container publication,
production documentation deployment, or post-publication check is verified.

Offline/local device build, install, and launch may proceed if it does not
contact ngrok or a live provider and does not collect Apple App Attest evidence.
Starting or reusing ngrok, contacting a provider for device proof, collecting
live App Attest evidence, or producing a protected device receipt required the
exact phrase `I authorize the scoped ngrok device proof.` The phrase was
supplied for a scoped run, but no tunnel, service, provider, App Attest, or
protected-device evidence was started or collected under that authorization.
The operator subsequently deferred App Intent/extension and physical
Android/Google Play evidence. Historical App Attest and predecessor signed
launch observations remain separately bound to their stated commits.

## What must remain gated

Do not advertise release-qualified Apple App Attest, Play Integrity,
immutable-image live-provider compatibility, cloud support, multi-replica
resilience, signed packages, or released package/image availability until the
matching external domain has an authenticated receipt for the exact candidate.
Missing credentials, devices, provider accounts, or registry access produce an
open gate, never a synthetic pass.
